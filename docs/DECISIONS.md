## Workflows and supply chain

- **SR-SUP-01/05/06/07:** the existing lockfile remains unchanged. All CI dependency installation uses `npm ci`; the dependency updater changes the lockfile with `npm update --package-lock-only` before `npm ci`. Every third-party action has a full SHA resolved using `git ls-remote`, with its version comment. Top-level permissions are only `contents: read`; additional rights are documented on the jobs that need them. User-controlled shell inputs go through environment variables.
- **SR-SUP-08:** GitHub reports BoatBuddy as public. Every job now explicitly uses GitHub-hosted `ubuntu-latest`, and the manual private-runner choice is removed. No repository variables, runner registrations or other GitHub settings were changed.
- **SR-SUP-09/11:** secret scanning retains blocking event-commit and working-tree scans. Full history remains an advisory release audit. Blocking Semgrep `p/security-audit` and `p/secrets` runs on PRs and releases; pinned zizmor reports workflow findings without blocking. PRs run lint, unit coverage, build and all offline guards. Live integration/browser/auth checks remain on main, scheduled or manual runs; they are not executed by PR validation.
- **SR-SUP-12 — Roger's approved free substitute:** every push to `main`, including documentation-only pushes, gets a provenance job. The pushed SHA must exactly match a merged PR into this repository's main branch. The PR head must have successful test, secret-scan and security workflows completed before merge; pending/failed additional checks or statuses also refuse. Missing evidence and API failures fail closed. GitHub omits run-to-PR associations after merged branches are deleted, so matching also uses exact head SHA, repository and branch. The production job requires this same reusable guard and can only promote `main`. CODEOWNERS covers workflows and the guard. This detects/refuses direct pushes at release time; it does not prevent GitHub from accepting the push, and administrators can still edit the controls. No branch-protection settings were changed.
- The manual gate-kit updater now proposes a branch/PR instead of pushing directly to main. PRs created using `GITHUB_TOKEN` do not automatically run normal checks: a maintainer must close/reopen the PR or push a reviewed change before it can satisfy the release guard. It cannot merge itself.
