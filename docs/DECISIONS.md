## Database changes and retained rights

- **SB-06:** every routine in `public`/`graphql_public` gets `search_path = pg_catalog, public, pg_temp`. The explicit final `pg_temp` prevents temporary-object shadowing; schema CREATE is revoked from browser roles and PUBLIC. The four app RPCs become SECURITY INVOKER and obey caller grants/RLS. Trigger functions alone retain elevation to write derived news/source links and hour totals, with no browser EXECUTE. Formatting helpers are invoked by those triggers and have no browser EXECUTE. `bump_extract_rate(text,timestamptz)` remains service-only with an empty search path. There is **no intended browser SECURITY DEFINER API** after 033.
- **SB-07 partial (corrected 2026-11-04):** revoke global and exposed-schema default rights for every actual object/default-ACL owner **the migrator may act as** (`pg_has_role(current_user, owner, 'SET')`, Postgres 16+). Tables, sequences, functions, types and schemas created by those roles get no automatic browser/PUBLIC rights. Existing service-role defaults remain. Future migrations must grant explicitly; the migration-grants baseline is unchanged. **Not reachable:** hosted Supabase's own `supabase_admin` default rights in `public` and `graphql_public` (browser grants on tables, sequences and functions it creates). The migrator `postgres` cannot act as `supabase_admin`, so Postgres refuses the change; the first release of 033 died on exactly that (staging run 41901180121). They only touch objects the platform itself creates there; every existing object is still checked by 033's final assertion. The migration names each skipped owner in a NOTICE. Cockpit's sql/088 and mitchind's 0017 stop at the same line.
- **SB-06 note (2026-11-04):** the search-path step skips routines the migrator does not own, by name. On both BoatBuddy projects that is one routine: `graphql_public.graphql(text,text,jsonb,jsonb)`, owned by `supabase_admin`, a SECURITY INVOKER stand-in for the absent `pg_graphql`. The SECURITY DEFINER refusal still covers every routine in `public`/`graphql_public`, whoever owns it.
- **Test fidelity (2026-11-04):** `scripts/test-database-security.mjs` now runs in the pinned image's own `postgres` database with the platform stand-ins created by `supabase_admin`, not in a fresh `createdb`.
